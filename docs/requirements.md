# Требования безопасности

[Паспорт](../PROJECT.md) · [Модель угроз](threat-model.md) · [Решения](design-decisions.md)

Критерий приёмки задаёт ситуацию и наблюдаемый результат. «Статус» — есть ли уже реализация и автоматический тест; выполненный тест — это проверка, а не только план.

<a id="sr-05"></a>
### SR-05. Доступ к ученику и связанным объектам — только в своей области

**Требование.** Администратор видит всех учеников. Преподаватель — только учеников с `tutor_id` = он, родитель — только с `parent_id` = он. Это правило действует для карточки, денежной истории, занятий, создания занятия и отчёта. Чужой и несуществующий объект неразличимы.  
**Защитное свойство.** Конфиденциальность денег и данных чужого ученика; невозможность изменить чужой баланс.  
**Критерий приёмки.** Преподаватель A запрашивает карточку ученика преподавателя B, создаёт ему занятие или отчитывается по занятию B → `404`, состояние БД не меняется. Родитель A запрашивает карточку или историю ребёнка родителя B → `404`. Запрос несуществующего id → тот же `404`.  
**Связи:** [T-03](threat-model.md#t-03) → [D-02](design-decisions.md#d-02). **Статус:** реализовано, тесты `tests/test_access.py`, `tests/test_lessons.py`.

<a id="sr-06"></a>
### SR-06. Преподаватель не получает контакты родителя и денежные данные

**Требование.** Ответы API для роли «преподаватель» содержат только поля, необходимые для ведения занятий: id, имя и класс ученика, сведения о занятиях. Телефон родителя, цена часа, баланс, оплаты и денежная история ему недоступны ни в одном ответе.  
**Защитное свойство.** Конфиденциальность персональных данных родителя и коммерческих данных школы от частично доверенного пользователя.  
**Критерий приёмки.** `GET /students` и `GET /students/{id}` от преподавателя → объекты ровно с полями `id`, `full_name`, `grade`. `GET /students/{id}/ledger` и `POST /students/{id}/payments` от преподавателя → `403`.  
**Связи:** [T-04](threat-model.md#t-04) → [D-02](design-decisions.md#d-02). **Статус:** реализовано, тесты `tests/test_access.py`.

<a id="sr-09"></a>
### SR-09. Уведомление о платеже принимается только от банка

**Требование.** Зачисление по уведомлению банка выполняется, только если подпись уведомления, вычисленная по секрету, известному банку и серверу, совпадает, а отметка времени уведомления не старше 5 минут. Иначе ответ `401` и никаких изменений.  
**Защитное свойство.** Подлинность источника денежного события.  
**Критерий приёмки.** Уведомление без подписи, с подписью другим ключом, с изменённой после подписи суммой или с отметкой времени старше 5 минут → `401`, баланс и журнал не меняются; корректно подписанное свежее уведомление → `200` и одна запись `payment`.  
**Связи:** [T-07](threat-model.md#t-07) → [D-04](design-decisions.md#d-04). **Статус:** спроектировано, не реализовано.

<a id="sr-10"></a>
### SR-10. Одна банковская операция зачисляется один раз

**Требование.** Повторное получение той же операции банка (по номеру операции) — повтор доставки, повтор ручного ввода или переигрывание — не создаёт второго зачисления. Тот же номер с другой суммой или для другого ученика отклоняется.  
**Защитное свойство.** Целостность баланса при штатных повторах доставки.  
**Критерий приёмки.** Повторное зачисление с тем же `external_id` и той же суммой → ответ с `duplicate: true`, баланс прежний; с тем же `external_id` и другой суммой → `409`.  
**Связи:** [T-08](threat-model.md#t-08) → [D-04](design-decisions.md#d-04). **Статус:** реализовано для ручного зачисления (`tests/test_access.py`); для уведомлений банка — в составе D-04.

<a id="sr-11"></a>
### SR-11. Тело запроса разбирается однозначно и в заданных пределах

**Требование.** Сервер принимает только `application/json` размером до 16 КБ в корректном UTF-8, ровно один JSON-объект без повторных ключей, без лишних полей и без неявного приведения типов. Денежные поля — целые в заданных диапазонах.  
**Защитное свойство.** Сервер и клиент одинаково понимают запрос; нельзя протащить скрытое поле или отрицательную сумму.  
**Критерий приёмки.** Тело с повторным ключом, NaN, двумя JSON-значениями или не-UTF-8 → `400`; с лишним полем, неверным регистром ключа, строкой вместо числа → `422`; тело больше 16 КБ → `413`; не JSON → `415`. Во всех случаях состояние не меняется.  
**Связи:** [T-09](threat-model.md#t-09); механизм — `app/input.py`. **Статус:** реализовано, тесты `tests/test_input.py`.
